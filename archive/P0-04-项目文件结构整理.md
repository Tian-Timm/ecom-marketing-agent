# P0 模块 04：项目文件结构整理

## 一、模块目标

解决本地同时存在“第5天作业”和“第五天作业”两套目录的问题，将第五天材料统一归档，同时保证线上部署文件、代码导入和 Git 历史不受影响。

## 二、目标结构

统一使用：

```text
第五天作业/
```

不再保留：

```text
第5天作业/
```

第五天目录采用单层扁平结构，文档直接放在目录下，不继续创建多层子目录。

## 三、整理前只读盘点

执行：

```powershell
Get-ChildItem -Recurse '第5天作业','第五天作业' |
  Select-Object FullName,Length,LastWriteTime
```

然后对同名或相似文件逐一比较：

- 文件名。
- 文件大小。
- 内容差异。
- 修改时间。
- 是否已被 Git 跟踪。
- 是否被其他 Markdown 或代码引用。

整理前输出迁移清单，不直接删除。

## 四、内容分类

### 应保留

- 项目最终交付记录。
- P0 模块规划。
- 端到端运行证据。
- 评测证据。
- 当天作业要求。
- 当天形成的代码或测试说明。

### 需要合并

- 两个目录中内容相同但命名不同的规划文档。
- 同一主题的旧版和新版文档。
- 重复的执行清单。

合并时保留：

- 最新事实。
- 有效执行步骤。
- 历史结果和证据。

删除重复段落，不删除独有信息。

### 不应移动

线上运行需要的根目录内容：

- `index.html`
- `vercel.json`
- `api/`
- `src/`
- `.agents/`
- `generated_output/`
- Python 和 Vercel 运行配置。

这些目录虽然位于根目录，但属于当前线上部署必要文件。

## 五、执行方式

1. 先建立完整文件对照表。
2. 对已跟踪文件优先使用 `git mv`。
3. 对未跟踪文件使用明确的单文件移动。
4. 每移动一批就检查引用。
5. 内容完全合并后，才删除空的“第5天作业”目录。
6. 不使用递归强制删除。
7. 不修改文件内容编码。
8. 不批量重命名代码和线上资源。

## 六、引用更新

搜索：

```powershell
rg -n "第5天作业|第五天作业" .
```

将所有有效引用统一为“第五天作业”。

重点检查：

- Markdown 链接。
- 交付记录中的证据路径。
- README 或 PRD 中的本地路径。
- 测试脚本是否引用作业目录。

## 七、Git 和密钥检查

整理后执行：

```powershell
git status -sb
git diff --check
```

确认：

- 没有 `.env`、`.env.local`、`.vercel` 进入暂存区。
- 没有图片附件 Token 或管理员口令进入新文档。
- Git 能清楚识别移动和新增文件。

## 八、回归测试

虽然本模块主要整理文档，仍需检查：

1. Python 模块导入不受影响。
2. 前端测试通过。
3. `generated_output` 路径不变。
4. Vercel 配置文件位置不变。
5. 根目录入口不变。

## 九、验收标准

- 只保留“第五天作业”目录。
- 目录内没有内容重复的文档。
- 项目最终交付记录保留完整。
- P0 规划文档完整。
- 所有本地链接可以解析。
- 线上运行文件未移动。
- Git 差异清晰，没有误删。

## 十、停止条件

- 两个同名文件内容不同且无法判断哪份应保留。
- 某个文件被代码或部署脚本依赖。
- 需要删除非空目录但尚未完成内容对比。
- Git 显示大量与本模块无关的删除。
- 发现密钥文件被跟踪。
