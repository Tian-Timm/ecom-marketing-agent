## 一、P0 目标

当前项目已经完成真实线上闭环，本轮 P0 不再重做飞书、DeepSeek、Python 出图和 Vercel 基础设施，重点解决两个问题：

1. 面试官第一次进入 Demo 时，可以在 60 秒内理解产品价值。
2. 页面和 PRD 中展示的能力，都能由真实运行证据支持。

本轮明确不处理简历文案，只调整 Demo、运行证据、PRD 和项目文件结构。

## 四、统一产品原则

### 面向体验者

体验者只需要知道：

- 数据从哪里来。
- 当前任务输入是什么。
- 系统判断是什么。
- 为什么被拦截。
- 通过后生成了什么。

不要在主要页面解释：

- 前端是否保存规则。
- Skill 与 Python 的内部职责边界。
- 是否复用历史图片。
- 服务端采用了什么内部文件结构。

这些内容应放在 PRD，而不是主要操作路径。

### 面向系统

- 不修改现有业务规则含义。
- 不放松写接口鉴权。
- 不开放任意飞书 Base。
- 不把密钥写入前端、文档或 Git。
- 不更换现有 Vercel 域名。
- 不为了演示效果伪造实时状态或运行数据。

## 五、统一视觉原则

- 保持高密度 SaaS 工作台结构。
- 使用中性色、白色卡片和单一低饱和绿色。
- 通过边框、间距和字阶建立层级。
- 不增加霓虹、发光和大面积渐变。
- 不增加轮播、自动播放或明显动画。
- 关键状态使用简洁 Badge。
- 任何新增内容不得挤压三栏工作区的主要操作空间。

## 六、统一技术约束

- 保留现有 JavaScript 依赖的全部 `id` 和 `class`。
- 不引入大型前端框架。
- 不在前端实现业务规则。
- 不在 HTML 中手写容易过期的运行数字；优先从经过白名单处理的证据数据读取。
- 页面加载失败时必须降级，不得导致整个 Demo 空白。
- 所有新增公开接口只能返回非敏感数据。

## 八、P0 完成定义

只有同时满足以下条件，P0 才算完成：

1. 新访客不阅读 PRD，也能在 60 秒内理解 Demo。
2. 页面展示的运行数字来自真实交付记录。
3. PRD 与当前线上能力、评测口径和已知限制一致。
4. 本地不存在“第5天作业”和“第五天作业”两套重复目录。
5. 原 Vercel 域名正常访问。
6. 飞书实时读取、受保护写入和图片交付没有回归。
7. 所有测试通过，且具备可用回滚版本。
