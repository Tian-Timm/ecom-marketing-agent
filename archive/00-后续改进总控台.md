# CHA CUP 后续改进总控台

## 使用方式

本目录中的文档是可以逐个交给 Gemini CLI 执行的独立任务包。请严格按编号顺序执行，不要同时运行多个模块。每完成一个模块，把 Gemini CLI 的执行总结、测试结果和变更文件列表交给 Codex 复核，再决定是否进入下一模块。

每次把文档交给 Gemini CLI 时，同时补充一句：

> 请先完整阅读本任务文档和项目根目录 AGENTS.md，只执行本模块授权的范围。遇到文档规定的停止条件时暂停，不要自行扩大权限。完成后按文档中的“回报格式”汇报。

## 总体禁止事项

- 不得把任何 App Secret、API Key、管理员口令或访问令牌写入 Git。
- 不得把管理员执行口令放进前端源码、本地存储或 URL。
- 不得开放无鉴权的写接口。
- 不得允许客户端传入任意 Base Token 或 Table ID。
- 不得为了“跑通”而跳过规则审查、语义复核或失败阻断。
- 不得强制重跑全部历史任务。
- 不得覆盖或删除现有 Base 记录。
- 不得更换 `https://cha-cup-marketing-demo.vercel.app` 这一简历链接。
- 不得推送到未明确授权的其他远程仓库或托管站点。

## Codex 总调控检查点

每个模块完成后，Codex 重点检查：

1. Gemini 是否扩大了修改范围。
2. 是否有密钥进入 Git 暂存区。
3. 是否保持原 Vercel 域名。
4. 是否仍然是“规则先审查，通过后出图”。
5. 是否有可复现的测试和证据。
6. 简历与 PRD 中的能力是否已经真实可演示。
