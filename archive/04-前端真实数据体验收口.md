# 模块 04：前端真实数据体验收口

## 前置条件

模块 03 已经完成真实端到端验收。不要在飞书链路尚未跑通时伪造“实时读取”状态。

## 任务目标

在不改变业务逻辑和 DOM 依赖的前提下，让前端更像可以给面试官直接体验的专业 SaaS 工作台。

## 必须保留

- 原页面所有被 JavaScript 使用的 `id` 和 `class`。
- 三栏结构：
  - 左：任务列表
  - 中：任务输入
  - 右：审查结果和图片
- 案例切换。
- 刷新。
- 选中任务执行。
- 待审查任务小批次处理。
- 管理员口令弹窗。
- 结构化结果查看与 JSON 复制。
- 图片下载。
- 原 Vercel 域名。

## 体验原则

面试官和体验者只需要理解：

1. 数据来自哪里。
2. 当前任务是否能出图。
3. 为什么被阻断。
4. 通过后生成了什么。
5. 系统是否真的调用了语义复核。

不要向普通体验者解释内部实现边界，例如：

- “前端不保存规则”
- “图层脚本只处理通过任务”
- “不会复用历史图片”
- “规则技能负责判断任务能否进入生产”

这些内容放在 PRD，不放在主要操作路径。

## 优先修改项

### P0：状态清晰

- 数据来源明确显示“飞书多维表格”。
- 区分“实时读取”和“线上快照”。
- DeepSeek 状态明确。
- 任务状态统一为：
  - 待处理
  - 通过
  - 需修改
  - 待复核
  - 失败
- API 加载时显示紧凑的加载状态。
- API 失败时保留可理解的错误提示和重试按钮。

### P0：结果清晰

- 合规任务优先展示图片和“审查通过”。
- 违规任务优先展示具体修改原因。
- 待复核任务说明需要人工确认，但不展示内部异常。
- DeepSeek 证据使用简短摘要，不堆模型原始 JSON。

### P1：操作清晰

- 只有实时写能力可用时才显示“处理待审查”。
- “执行所选任务”在无选中任务或能力未启用时禁用。
- 管理员口令只在需要执行时出现。
- 执行中禁止重复点击。
- 操作完成后刷新当前任务状态，不跳回第一条任务。

### P1：响应式

至少验证：

- 1440×900 桌面
- 1920×1080 桌面
- 768×1024 平板
- 390×844 手机

不得恢复固定 `1920×1080` 舞台缩放。

## 视觉标准

- 高信息密度，规整网格。
- Zinc/Slate 中性色和白色卡片。
- 只保留一个低饱和绿色主色。
- 错误使用克制的红色。
- 边框优先于阴影。
- 极少动画，只保留轻微 Hover。
- 字号最小不低于可读范围。
- Badge 文本必须在边框内垂直水平居中。

## 技术限制

- 不引入大型前端框架。
- 不把业务规则复制到前端。
- 不在前端模拟合规结果。
- 不修改后端固定 Base 限制。
- 不增加公开写接口。
- 不把管理员口令持久化。
- 不删除现有功能换取视觉效果。

## 验证

1. 运行前端结构测试。
2. 在本地或线上逐个点击四个案例。
3. 检查实时 Base 任务。
4. 检查合规、阻断、待处理、失败四类状态。
5. 检查图片加载失败时的降级提示。
6. 检查控制台无错误。
7. 截取桌面和手机关键页面。

## 验收标准

- 面试官 10 秒内能理解输入、审查和输出。
- 所有原功能继续可用。
- 页面没有内部技术说明占据主要空间。
- 不出现文字溢出 Badge、按钮或卡片。
- 手机端没有横向硬缩放。
- 线上实时状态和实际能力一致。
