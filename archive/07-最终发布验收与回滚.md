# 模块 07：最终发布验收与回滚

## 前置条件

- 模块 01 至 06 已完成或明确跳过。
- 所有代码修改已经通过测试。
- 用户确认最终要发布到现有 Vercel 项目。

## 任务目标

完成最终代码提交、生产发布、原链接验收和回滚准备，确保用户已经发出的简历和求职信链接继续有效。

## 发布前检查

1. 检查工作区：

```powershell
git status -sb
git diff --check
```

2. 检查密钥：

- `.env`
- `.env.local`
- `.vercel`
- App Secret
- DeepSeek Key
- 管理员口令

这些内容必须处于忽略状态，不能进入暂存区。

3. 运行完整测试：

```powershell
python -m unittest discover `
  -s .agents/skills/simple-visual-compliance/tests `
  -p "test_*.py"

python .agents/skills/simple-visual-compliance/scripts/evaluate_fixture.py
```

4. 生产构建：

```powershell
$env:UV_CACHE_DIR = Join-Path $env:TEMP 'cha-cup-uv-cache'
npx.cmd --yes vercel pull --yes --environment production
npx.cmd --yes vercel build --prod
```

## Git 提交

- 只提交本轮改动。
- 不使用 `git add -A`，除非已经确认全部工作区变更属于本项目。
- 提交信息准确描述功能。
- 推送到：

```text
https://github.com/Tian-Timm/ecom-marketing-agent
```

- 默认推送当前 `main`，除非 Codex 明确要求新分支。
- 不推送到其他远程仓库或托管服务。

## Vercel 发布

```powershell
npx.cmd --yes vercel deploy --prebuilt --prod --yes
```

必须看到：

```text
Aliased https://cha-cup-marketing-demo.vercel.app
```

如果只得到新的随机部署域名但未设置原 Alias，任务不算完成。

## 生产验收清单

### 首页

- `https://cha-cup-marketing-demo.vercel.app` 返回 200。
- 标题和主要工作区正常。
- 原案例可以切换。
- 图片可加载。
- 没有横向硬缩放。

### 状态接口

- `/api/status` 返回 200。
- `online=true`。
- `mode=live`。
- `semantic_review=true`。
- `feishu_read=true`。
- `feishu_write=true`。

### 任务接口

- `/api/tasks` 返回固定 Base 任务。
- 不返回敏感信息。

### 写接口

- 无口令请求返回 401。
- 错误口令返回 401。
- 不要在最终发布验收时强制重跑全部任务。
- 如需验证正确口令，只执行专用验收任务。

### 图片

- 合规任务图片可展示和下载。
- 图片代理不能读取不属于固定 Base 的 Token。

### 响应式

- 桌面和手机各检查一次。
- Badge、按钮和状态文字不溢出。

## 回滚方案

记录发布前的稳定提交 SHA 和 Vercel Deployment ID。

如果新版本出现 P0 故障：

1. 优先在 Vercel 控制台把上一个稳定 Deployment 设为 Production。
2. 不删除当前失败 Deployment，保留排查证据。
3. Git 使用正常的修复提交回滚，不使用 `git reset --hard`。
4. 如果只是飞书服务异常，临时移除飞书生产变量，使系统回到快照模式，保证页面可访问。
5. 原域名始终保持：

```text
https://cha-cup-marketing-demo.vercel.app
```
