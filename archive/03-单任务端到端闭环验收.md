# 模块 03：单任务端到端闭环验收

## 前置条件

- 模块 02 已完成。
- `/api/status` 显示 `online=true`。
- 飞书读取、写入、DeepSeek 和图片交付能力均为 true。
- 用户持有 `DEMO_ADMIN_TOKEN`。

## 任务目标

用一条新建的验收任务证明完整链路：

飞书 Base 输入 → 确定性规则 → DeepSeek 语义复核 → Python 图片组装 → 飞书图片附件上传 → 状态和证据回写 → 前端展示。

## 测试数据原则

- 新建专用任务，不覆盖现有 `MKT-001` 至 `MKT-010`。
- 建议任务编号：`MKT-E2E-001`。
- 使用合规文案，确保第一轮可以出图。
- 不删除该记录，保留为作品集运行证据。
- 不使用真实客户数据。

建议输入：

```text
任务ID：MKT-E2E-001
图片类型：电商主图
画布比例：1:1
活动价：129
最低允许价格：89
投放日期：活动周期内任一天
活动开始日期：当天
活动结束日期：当天后 7 天
主文案：城市轻装 随时出发
补充要求：白底展示产品主体，保持产品外观不变
审查状态：待处理
```

日期必须按执行当天重新计算，不能使用已经过期的固定日期。

## 执行步骤

1. 读取任务表字段定义，确认字段名称和类型。
2. 在飞书任务表新建 `MKT-E2E-001`。
3. 刷新线上 Demo。
4. 确认前端出现该任务，状态为“待处理”。
5. 选择该任务，点击“执行所选任务”。
6. 输入管理员执行口令。
7. 等待任务完成，不重复点击。
8. 检查前端、API 和飞书三处结果。

## 前端验收

- 状态从“待处理”变为“通过”。
- 展示 DeepSeek 语义复核摘要和置信度。
- 展示最终营销图片。
- 图片可以打开和下载。
- 处理记录依次包含：
  - 信息整理
  - 规则审查
  - 语义复核
  - 图片生成
  - 飞书交付
- 不显示密钥、内部异常栈或服务器路径。

## 飞书回写验收

`MKT-E2E-001` 应包含：

- 审查状态：审查通过
- 问题说明：为空或明确无问题
- 生成图片链接：存在
- 生成图片：存在附件
- 处理时间：存在
- 输入指纹：存在
- 处理版本：`2026-07-31.2` 或后续明确版本

输入字段不得被输出内容覆盖。

## 幂等性验收

再次执行同一任务：

- 不重复上传图片。
- 不重复写入相同结果。
- 返回或记录 `SKIPPED_UNCHANGED`。
- 输入指纹保持一致。

然后只修改主文案中的一个安全词，再执行：

- 输入指纹发生变化。
- 任务重新审查。
- 生成新的处理时间和结果。

## 失败场景验收

新增或复制一条专用违规任务 `MKT-E2E-BLOCKED`：

```text
主文案：全网第一的城市保温杯
```

预期：

- 状态为“需修改”。
- 问题说明包含禁用词原因。
- 不生成图片。
- 不上传图片附件。
- 如果曾有同任务编号的旧图片，结果不得错误复用。

## 验收标准

- 一条合规任务完成真实出图和飞书附件回写。
- 一条违规任务在生成前阻断。
- 同一输入重复执行不会重复上传。
- 前端、API、飞书三处状态一致。
- 整个过程没有人工修改系统输出字段。

## 证据保存

保存以下非敏感证据：

1. `/api/status` 能力状态，隐去所有令牌。
2. 合规任务前端结果截图。
3. 合规任务飞书回写截图。
4. 违规任务阻断截图。
5. 单次执行耗时。
6. 幂等跳过结果。

证据文件放入 `第五天作业`，文件名使用自然中文，不包含密钥。
