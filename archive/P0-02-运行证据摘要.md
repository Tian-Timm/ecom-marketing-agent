# P0 模块 02：运行证据摘要

## 一、模块目标

在 Demo 中增加一个克制、可信的运行证据区域，让面试官看到项目不是纯交互原型，而是经过自动化测试和固定评测的系统。

该模块不重新评测，不修改现有指标，只展示《项目最终交付记录》中已经确认的数据。

## 二、允许展示的证据

### 自动化与评测

- 自动化测试：85/85（根目录 49/49，合规 Skill 36/36）
- 任务状态一致：10/10
- 异常任务检出：6/6
- 规则码一致：10/10

### 真实运行

- 静态快照：规则审查和确定性图片生成已重新执行
- 公开实时运行：重新读取固定 Base、执行规则和 DeepSeek，`live_readonly`
- 公开写入：不会上传图片或回写飞书
- 管理员幂等：输入未变化时仍可返回 `SKIPPED_UNCHANGED`

### 系统能力

- 公开模式从固定演示 Base 实时读取，但不写入飞书。
- 管理员模式保留受保护的飞书回写和图片附件交付。
- 公开实时运行会调用 DeepSeek；静态快照不把未配置的在线服务写成已执行。

## 三、禁止公开的内容

- App Secret。
- API Key。
- 管理员口令。
- Vercel Token。
- 完整飞书文件 Token。
- 内部堆栈和服务器路径。
- 可以被用于调用写接口的任何凭据。

页面不需要展示具体 `file_token`。

## 四、证据数据设计

### 推荐方案

新增一份公开白名单数据：

```text
generated_output/public_evidence.json
```

建议结构：

```json
{
  "updated_at": "2026-08-01T09:49:58+00:00",
  "git_commit": "707190f",
  "pipeline_version": "2026-08-01.2",
  "rules_version": "2026-07-30.1",
  "tests": {
    "passed": 85,
    "total": 85
  },
  "evaluation": {
    "status_correct": 10,
    "status_total": 10,
    "anomalies_detected": 6,
    "anomalies_total": 6,
    "rule_codes_correct": 10,
    "rule_codes_total": 10
  },
  "e2e": {
    "mode": "static_snapshot",
    "passed_duration_seconds": 1.122,
    "blocked_duration_seconds": 0.008,
    "idempotency": {
      "admin": "SKIPPED_UNCHANGED",
      "public": "REEXECUTES_EVERY_TIME"
    }
  },
  "sample_note": "定向构造的 10 条项目评测集，其中 6 条为边界异常任务。"
}
```

不得把整份内部交付记录直接暴露为 API。

### 数据更新原则

- 证据数据由发布流程生成或人工确认后更新。
- 前端只读取白名单字段。
- 页面加载失败时隐藏证据区，不影响任务工作台。
- 不在 `index.html` 多处重复硬编码数字。

## 五、页面布局

证据区建议放置在三栏工作区之后、页面底部之前。

使用一个紧凑区域，分为四个证据单元：

1. `85/85` 自动化测试
2. `10/10` 状态一致
3. `6/6` 异常检出
4. 静态快照耗时（不冒充在线端到端耗时）

下方增加一行小字：

```text
基于 10 条定向项目评测集，其中 6 条为边界异常任务；最近更新见处理版本。
```

不要写“行业领先”“生产级准确率”等扩大结论。

## 六、交互设计

- 默认只显示摘要。
- 可以提供“查看评测说明”链接，跳转 PRD 对应章节。
- 不增加图表轮播。
- 不增加自动计数动画。
- 不展示原始日志。
- 不要求访客登录。

## 七、修改范围

预计修改：

- `index.html`
- `generated_output/public_evidence.json`
- `.agents/skills/simple-visual-compliance/tests/test_frontend_demo.py`
- 必要时增加证据数据结构测试。

原则上不修改：

- `/api/run`
- `/api/sync`
- 飞书适配器。
- DeepSeek 调用。
- 规则判断。

## 八、测试方案

1. 证据 JSON 可以正常解析。
2. 页面正确显示当前证据 JSON 中的测试、评测和静态快照摘要；不把静态耗时解释为在线端到端耗时。
3. 样本说明同时出现。
4. 数据文件不存在或请求失败时，主页面仍可使用。
5. 页面不显示 `file_token`、密钥或管理员口令。
6. 手机端证据单元不溢出。
7. PRD 链接在新标签页打开。
8. 自动化测试通过。

## 九、验收标准

- 面试官能快速判断项目具有真实运行证据。
- 所有数字与《项目最终交付记录》一致。
- 明确说明样本为 10 条定向评测集。
- 证据区不抢占主要任务工作区。
- 不公开敏感字段。
- 证据加载失败不会影响 Demo。

## 十、停止条件

- 需要从生产日志直接向公众暴露数据。
- 无法保证证据接口不返回敏感字段。
- 展示数据与最终交付记录不一致。
- 需要重新执行真实飞书任务才能完成本模块。
