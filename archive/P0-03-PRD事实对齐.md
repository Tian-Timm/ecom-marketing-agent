## 四、建议 PRD 结构

### 1. 项目摘要

用一屏说明：

- 面向电商营销图批量生产。
- 解决价格、日期、禁用词、产品外观和视觉规范风险。
- 采用规则、LLM 和 Python 确定性组装的混合架构。
- 通过飞书 Base 完成输入和结果回写。

### 2. 用户与场景

主要用户：

- 电商运营。
- 品牌设计师。
- 营销素材审核人员。

主要场景：

- 大促前批量准备营销图。
- 出图前检查价格和广告文案。
- 使用统一模板快速生成不同尺寸素材。

### 3. 问题定义

说明：

- 手动套版效率低。
- 业务输入错误会直接进入图片。
- 纯生图模型会修改产品外观或产生中文错误。
- 事后发现问题的返工成本高。

如无外部调研报告，不把“10～20 分钟”描述为整个行业的统一事实；可写成项目案例观察或流程估算。

### 4. 产品目标与非目标

目标：

- 出图前阻断业务红线。
- 使用 LLM 补充语义风险判断。
- 通过确定性图层组装保证价格和中文稳定。
- 将状态、原因和图片附件回写飞书。

非目标：

- 不做开放式端到端文生图。
- 不让 LLM 修改价格。
- 不推断缺失字段。
- 不替代最终品牌人工审核。

### 5. 输入与输出

输入：

- 商品资料。
- 营销任务。
- 规则文件。
- 品牌模板和产品素材。

输出：

- 审查状态。
- 违规原因。
- DeepSeek 语义复核摘要。
- PNG 图片。
- 飞书图片附件和链接。
- 输入指纹、处理版本和处理时间。

### 6. 系统流程

```text
飞书 Base
→ 字段规范化
→ 确定性业务规则
→ DeepSeek 语义复核
→ 通过后 Python 图层组装
→ 飞书附件上传与状态回写
→ Dashboard 展示
```

### 7. 规则和模型边界

明确区分：

- 确定性规则：价格、日期、比例、直接禁用词和必要字段。
- DeepSeek：语义宣传风险、产品外观修改要求、含混指令。
- Python：只负责确定性渲染和产物校验。
- 前端：展示服务端结论，不自行判断。

### 8. 状态设计

统一说明：

- 待处理。
- 审查通过。
- 需修改。
- 待人工复核。
- 执行失败。

说明每种状态是否允许生成图片。

### 9. 安全和稳定性

包括：

- 固定演示 Base。
- 写接口管理员口令。
- 10 分钟单 IP 6 次限制。
- 单批最多 3 条。
- 输入指纹幂等。
- 模型异常不默认放行。
- 飞书异常时降级到快照模式。

### 10. 评测与真实证据

展示：

- 30/30 自动化测试。
- 10 条定向评测集。
- 6 条边界异常。
- 10/10 状态一致。
- 6/6 异常检出。
- 10/10 规则码一致。
- 合规和违规端到端耗时。
- 幂等验证。

必须同时注明样本规模有限。

### 11. 已知限制

保留并适当补充：

- 评测集规模小。
- 当前模板和品牌数量有限。
- 公开访客不能直接写飞书。
- 语义规则不能覆盖全部广告法规。
- 当前只支持固定演示 Base。
- 尚未开放 CSV、JSON 和动态 Base 接入。

### 12. 后续路线

按顺序写：

1. CSV、JSON 导入。
2. 受控的飞书 Base 接入。
3. 扩大评测集。
4. 多模板和出图后视觉复检。
5. 运行记录和运营统计。

## 五、修改流程

1. 完整读取现有 PRD。
2. 输出章节对照表：保留、改写、新增、删除。
3. 不直接整篇覆盖。
4. 优先局部更新，保留有价值的背景和 Badcase。
5. 更新评测和线上能力。
6. 增加已知限制。
7. 更新 Demo 和 Base 链接。
8. 写入后重新读取全文。
9. 检查标题、层级、重复内容和链接。

## 六、文风要求

- 使用准确中文。
- 避免每个中文概念后附英文括号。
- 可以使用 P0、LLM、API、Skill 等通用行业表达。
- 不写“完美”“生产级准确率”“全面解决”等扩大结论。
- 技术细节服务于产品判断，不写成代码说明书。
- 文档标题自然，不包含“猹馆项目日志”。

## 七、验收标准

- 3 分钟内可以理解项目背景、判断、流程和结果。
- 所有已实现能力与最终交付记录一致。
- 评测数据注明样本口径。
- 已知限制真实、完整。
- 后续路线与当前计划一致。
- Demo、Base 和文档链接均正确且不重复。
- 未修改简历内容。

## 八、停止条件

- 无法确认目标 Wiki 节点。
- 当前文档存在未保存或冲突版本。
- 缺少编辑权限。
- 需要删除大量原文但尚未向用户展示差异。
- 发现最终交付记录与线上事实直接冲突。
