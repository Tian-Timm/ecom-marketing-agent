# 业务语义层接入与迁移说明

## 目标与边界

本系统将飞书多维表格的物理表名、字段名与业务语义分离。**发现工具负责首次接入；业务语义层负责日常稳定运行。**

文件导入（CSV/JSON）仍可通过 `dataset-standardizer` 用宽松别名清洗；这不适用于已接入的飞书正式运行。飞书正式运行只接受已激活的配置，并以 `source_id + task_id` 精确定位数据，绝不以默认商品、默认价格或默认关键字段补齐。

## 架构与数据流

```text
首次接入
Base 表/字段/样本（只读）
  -> 发现候选（含置信度与理由）
  -> 页面人工确认映射
  -> DRAFT SourceConfig + 只读 dry-run
  -> 显式激活 ACTIVE revision

正式运行
source_id + task_id
  -> ACTIVE SourceConfig / 字段 ID 漂移校验
  -> 精确任务与商品读取、严格转换
  -> PreparedTask + SourceReceipt
  -> 合规审查 / 语义复核 / 确定性渲染
  -> 上传图片 + 仅向 Receipt 指定记录回写
```

模块职责：

- `src/business_semantics/models.py`：版本化 `DataSourceConfig`、标准商品/任务、键与回执。
- `discovery.py`：只读表/字段/样本发现、候选建议和结构漂移判断。
- `confirmation.py`、`repository.py`：人工选择编译、dry-run 证据、不可变 DRAFT revision 和 CAS 激活指针。
- `runtime.py`：`prepare_task(source_id, task_id)`；严格转换并生成 `PreparedTask`。
- `orchestration.py`：复用既有审查/渲染流水线，按回执定点上传和回写。
- `src/web_api.py`：管理员受保护的发现、确认、激活、配置源任务、运行和图片代理接口。

## 领域词汇

| 术语 | 含义 |
| --- | --- |
| Data Source | 一个稳定的业务数据源，由 `source_id` 标识；Base token 只是连接细节。 |
| ProductKey / TaskKey | 分别是 `source_id + product_id`、`source_id + task_id`，跨源同 ID 不会混淆。 |
| SourceConfig | 人工确认后的表、字段 ID、字段类型、商品关联和回写配置，带 revision。 |
| DRAFT / ACTIVE | DRAFT 已通过只读验证但不可运行；只有显式激活后的有效 revision 可运行。 |
| PreparedTask | 从语义层交给合规/渲染层的不可变标准任务。 |
| SourceReceipt | 本次读到的商品/任务表和 record ID；回写只能使用它。 |

## 首次接入操作

1. 打开工作台，输入管理员口令（仅在当前页面内存保留）。
2. 输入小写 `source_id`、显示名、Base URL 或 token，以及已部署的 `credential_ref`；不要输入任何密钥。
3. 点击“发现”：系统只读取表、字段和少量样本，显示候选的 HIGH/MEDIUM/LOW 置信度及理由。
4. 分别选择商品表和任务表。每个语义字段都能手动选择该表的任意字段；未推荐项会标为“未推荐/需人工确认”。
5. 输出回写字段自动跟随任务表，不可选其他表。点击“确认”会执行只读 dry-run 并保存 DRAFT revision。
6. dry-run 成功后点击“激活”。运行时选择该数据源，再执行单任务或待审查同步。

必填映射如下：

| 区域 | 必填语义 |
| --- | --- |
| 商品表 | `product_id`、`product_name`、`min_price` |
| 任务表 | `task_id`、`product_id`、`img_type`、`aspect_ratio`、`main_text`、`promo_price`、`deploy_date` |
| 回写（同一任务表） | `status`、`issues`、`processed_at`、`input_hash`、`pipeline_version`，以及 `image_attachment` 或 `image_url` 至少一个 |

可选字段包括商品/品牌图片、补充文案和活动周期。已映射素材却无法下载时会失败，不会偷偷使用默认素材。

商品关联策略：

- `DIRECT_VALUE`：任务表的 `product_id` 为文本或数字，按值精确匹配商品表。
- `LINKED_RECORD`：任务表的商品字段为飞书关联记录，按关联 record ID 精确读取。
- `AUTO`：根据已确认字段类型在以上两者中选择；首次接入推荐此项。

## 环境与持久化

部署环境需要设置以下变量，值均不得提交到仓库：

| 变量 | 作用 |
| --- | --- |
| `SOURCE_CONFIG_DIR` | 非 Vercel 环境中可写、真实持久的数据源配置目录；未设置时本地使用 `runtime/source_configs/`。 |
| `DEMO_ADMIN_TOKEN` | 配置化源读取、接入、运行和图片代理的管理员口令。 |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | `FEISHU_PRIMARY_APP` 对应的飞书应用身份。 |
| `FEISHU_CREDENTIAL_<NAME>_APP_ID` / `FEISHU_CREDENTIAL_<NAME>_APP_SECRET` | 命名凭据引用 `FEISHU_CREDENTIAL_<NAME>` 的身份；`<NAME>` 只能使用大写字母、数字和下划线。 |
| `DEEPSEEK_API_KEY` | 语义复核服务身份；不可用时任务进入受控失败/人工复核路径，而非默认放行。 |

本地或具有真实持久挂载的**非 Vercel**环境可使用 `SOURCE_CONFIG_DIR`，并执行确认和激活。当前 Vercel 版本的唯一实现是本地文件 `SourceConfigRepository`；无论是否设置 `SOURCE_CONFIG_DIR`，它都被标记为 ephemeral，服务端拒绝动态确认和激活，避免临时目录被误认为正式配置。要在 Vercel 开放动态接入，必须先实现并接入明确的外部持久 `SourceConfigRepository` 后端（例如数据库或对象存储）；不能仅靠目录环境变量解决。

## 安全模型与错误处理

- Base token 与凭据引用可被服务器用于连接，但 API 响应、前端和 SourceConfig 中不写入应用密钥；`credential_ref` 只解析受限环境变量名称。
- 发现无写操作；配置源的 `GET /api/tasks?source_id=...`、`GET /api/sources`、`GET /api/image?source_id=...` 均需管理员口令，但不消耗写入配额。
- `POST /api/discover`、`/api/confirm`、`/api/activate`、`/api/run`、`/api/sync` 需管理员口令并受写入节流保护。
- 图片代理先验证 file token 属于当前 `source_id` 的已映射附件字段；跨数据源 token 被拒绝。

| HTTP 状态 | 含义 |
| --- | --- |
| 400 | 请求、映射或字段值不合法；包括缺少必填回写字段。 |
| 401 | 管理员口令无效。 |
| 404 | 找不到配置、任务或商品。 |
| 409 | revision CAS 冲突、重复运行锁、结构漂移或不可运行状态冲突。 |
| 503 | 配置存储、飞书凭据或外部服务当前不可用；响应不回显上游敏感诊断。 |

## 从固定演示迁移

固定演示 Base 的 legacy 路径仍可使用：未携带 `source_id` 的 `/api/tasks`、`/api/run`、`/api/sync` 继续走原有固定演示适配器。它不是配置化运行的默认数据源。

当前固定演示任务输入契约没有可用于配置化精确商品读取的 `product_id` 关联字段。因此不能直接把它激活为配置化源。迁移时应在真实 Base 中（由业务管理员操作）：

1. 新建任务侧的文本 `product_id` 或关联记录字段，并为历史/待处理任务补齐值。
2. 准备商品表的 `product_id`、商品名和最低允许价格。
3. 新建独立回写字段，不要复用主文案、补充要求或输入字段。
4. 通过页面发现、确认、dry-run、激活；先选一条非生产任务验证后再批量同步。

本文不修改远端 Base，也不伪造远端字段是否存在。

## 版本回滚与运维

每次确认都会生成新 DRAFT revision。若新版本已激活但需要回退：以当前 ACTIVE revision 为 `expected_active_revision`，显式激活已通过 dry-run 的旧 revision。CAS 不匹配会返回 409，先刷新当前活动版本再决定是否重试。不要手改配置 JSON 或运行时目录。

不应把示例 SourceConfig 放进 `runtime/source_configs/`：该目录是运行时持久化位置，示例应只存在于本文档的字段表和请求说明中。
